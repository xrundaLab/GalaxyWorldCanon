# 银河剧情游戏世界观与单集生产圣经 v0.1

## 0. 文档定位

本稿是银河 APP「沉浸游戏」学习方式的**剧情游戏生产上游约束**，供李光及相关 Agent 在把课程教案转为沉浸式课件时使用。

它不替代课程教案，不要求首发实现真正的多线电子游戏，也不替代后续完整 IP 设定集。它要解决的是当前最现实的问题：让每一节课都有可读、可看、可参与的剧情体验，同时不再反复落入“飞船坏了、伙伴装笨、知识硬插入”的同质套路。

### 0.1 模式命名

- 产品既有代名：沉浸游戏
- 本阶段正式中文名：**银河剧情游戏**
- 英文功能名：**Narrative Learning Adventure**
- 用户解释：在故事中观察、判断、行动，把知识变成自己的能力。

“剧情游戏”强调故事、互动和代入感；不承诺其为大型电子游戏或复杂分支 RPG。

### 0.2 首发边界

- 每课以线性主线加少量关键决策为主。
- 不要求长期积分、装备、交易、开放地图或复杂多结局。
- 每课优先做到：故事成立、角色可信、任务清楚、互动有意义、学习结果可理解。
- 游戏感来自目标、选择、结果、角色关系和视觉奇观，而不是强行堆积分。

# 1. 世界观硬约束

## 1.1 一句话母设定

学习者从自己的初始宇宙进入 AI 知识银河，在四大星域结识四位糖基生命伙伴；他们通过观察、判断、创造和协作，把陌生问题转化为可带回现实的能力、作品与经验。

## 1.2 世界观在剧情游戏中的职责

世界观只做四件事：

1. 给学习者稳定的身份：我是探索者和行动者，不是旁观者。
2. 给角色稳定的关系：伙伴有性格、专长和成长，不是提问机器。
3. 给单集稳定的场域：星舰、星域、档案、信号、委托、观测与行动。
4. 给学习结果稳定的意义：我解决了一个问题，并留下可见证的旅程痕迹。

世界观不应成为一套需要孩子背诵的词典。除“星域、伙伴、航行、任务、档案”等低解释成本词汇外，糖能、代谢、结晶等抽象表达仅在需要时轻量使用。

## 1.3 用户身份与角色边界

- 用户是主角、决策者和最终行动者。
- 伙伴提供不同视角、证据、工具或情绪支持，但不替用户作答。
- AI 工具是可调用的能力，不是万能魔法。
- 错误不是“角色笨”，而是一次会带来合理后果、可被理解和修正的尝试。

# 2. 四位伙伴角色卡

## 2.1 角色资产总规则

- 四位伙伴是好朋友，分别对应创想、探索、筑梦、先锋四大星域。
- 拓奇是创想星域那位矮胖糖基伙伴的正式 IP 名；其宇航服形态不是金属机器人替身。
- 其余三位正式姓名尚未在本稿锁定。生成脚本时使用“探索伙伴、筑梦伙伴、先锋伙伴”等角色位，不得自行创造并固化正式姓名。
- 四位伙伴均可有宇航服变身形态；必须优先调用既有 IP 素材库，禁止默认生成带 RunS 标识的泛机器人。

## 2.2 创想星域伙伴：拓奇 Toki

| 字段     | 设定                       |
| ------ | ------------------------ |
| 核心气质   | 好奇、弹性、跳跃、热烈，对未知事物有天然兴趣。  |
| 专长     | 发现怪问题、提出新角度、把普通事物想象成新可能。 |
| 有趣缺点   | 容易兴奋过头，一次想同时尝试太多方向。      |
| 与用户关系  | 激发“我也想试试”的第一位同行伙伴。       |
| 典型剧情功能 | 发现异常、提出大胆假设、引出创意挑战。      |
| 禁止写法   | 反复装笨、只会夸张惊呼、每次都等用户纠错。    |

## 2.3 探索星域伙伴：线索型伙伴

| 字段     | 设定                     |
| ------ | ---------------------- |
| 核心气质   | 冷静、敏锐、爱观察细节，享受从混乱中找规律。 |
| 专长     | 收集线索、分类、比较、核查、发现遗漏。    |
| 有趣缺点   | 容易分析过头，迟迟不愿下结论。        |
| 与用户关系  | 让用户学会“先看证据，再作判断”。      |
| 典型剧情功能 | 调查谜案、读取档案、拆解信号、发现矛盾。   |
| 禁止写法   | 变成只报术语的百科助手，或代替用户完成推理。 |

## 2.4 筑梦星域伙伴：建造型伙伴

| 字段     | 设定                          |
| ------ | --------------------------- |
| 核心气质   | 耐心、灵巧、务实，喜欢把想法变成真实可用的东西。    |
| 专长     | 原型、搭建、组合、测试、迭代与修复。          |
| 有趣缺点   | 有完美主义，会因舍不得交付而错过行动时机。       |
| 与用户关系  | 让用户理解“做出来并不等于结束，还要试一试”。     |
| 典型剧情功能 | 原型工坊、建造委托、作品测试、功能修正。        |
| 禁止写法   | 只负责说“太棒了”，或把制作过程写成无阻力的一键成功。 |

## 2.5 先锋星域伙伴：领航型伙伴

| 字段     | 设定                            |
| ------ | ----------------------------- |
| 核心气质   | 稳定、可靠、有责任感，敢面对复杂现实问题。         |
| 专长     | 协作分工、风险判断、权衡取舍、推动真实行动。        |
| 有趣缺点   | 容易把责任全扛在自己身上，偶尔过快进入“必须解决”的状态。 |
| 与用户关系  | 让用户意识到能力最终要用于理解他人、解决真实问题。     |
| 典型剧情功能 | 团队分歧、真实委托、伦理两难、方案决策。          |
| 禁止写法   | 说教式队长，或把价值判断写成唯一标准答案。         |

## 2.6 四人关系规则

- 拓奇提供可能性，探索伙伴要求证据，筑梦伙伴推动实现，先锋伙伴追问影响与责任。
- 角色冲突来自方法差异，不来自互相否定或故意犯蠢。
- 每集最多让两位伙伴承担主要对白；其余角色可通过讯息、档案、短暂客串或章节钩子出现。
- 同一伙伴不得连续多集承担完全相同的功能。

# 3. 单集剧情游戏结构卡

每节课生产前必须填写以下字段。空字段不得直接进入文生图或脚本阶段。

| 字段   | 必填内容                | 约束               |
| ---- | ------------------- | ---------------- |
| 本集标题 | 有画面感的短标题            | 不直接复述知识术语。       |
| 本集类型 | 从机制库选择一种            | 不得连续三课同类型。       |
| 主角伙伴 | 用户 + 1 至 2 位伙伴      | 按星域优先选用。         |
| 开场异象 | 值得追查的具体事件           | 禁止默认“飞船又坏了”。     |
| 任务目标 | 用户此集必须完成什么          | 一句话说清，可被验证。      |
| 生活案例 | 教案中的真实校园、家庭或社会情境    | 作为案例档案，不硬改成外星设定。 |
| 学习动作 | 判断、分类、比较、设计、核验、协作之一 | 每集只突出一个主动作。      |
| 关键互动 | 1 次核心选择或轻操作         | 题干与选项同屏，保留任务卡。   |
| 错误后果 | 具体、合理、可恢复           | 先说明为什么，不羞辱用户。    |
| 结果变化 | 任务世界发生什么改变          | 必须与本集目标相连。       |
| 尾声钩子 | 可选的一句新线索或人物关系变化     | 不强行制造大危机。        |

## 3.1 推荐的单集节奏

1. **冷开场**：先看到不寻常的现象、来信、档案或委托。
2. **任务定向**：用一句话说清“现在要弄明白/完成什么”。
3. **案例进入**：调取教案的真实生活场景，成为本集需要处理的材料。
4. **观察与判断**：伙伴提出不同看法，用户获得关键互动。
5. **知识介入**：用最少的知识解释支持行动，不写成课堂念稿。
6. **行动结果**：选择或操作改变案例结果、角色理解或任务状态。
7. **余韵收束**：留下一个纪念物、记录或关系变化；可有弱钩子。

## 3.2 单集长度控制

- 总时长以 5 至 8 分钟为目标；不以页数堆时长。
- 单次角色台词优先控制在 1 至 2 句。
- 连续纯剧情页面不超过 3 页；之后必须出现新信息、场景变化、任务推进或用户行动。
- 核心互动前，屏幕持续显示“眼前材料 / 当前任务 / 成功条件”三行任务卡或等效信息。

# 4. 叙事机制库

下列是原创生产可复用的叙事结构，不是对任何现有影视、小说、游戏的改写。

| 类型   | 适合的课程内容        | 基本机制                   |
| ---- | -------------- | ---------------------- |
| 星际档案 | 概念辨析、信息来源、事实核查 | 从一份异常档案里找出遗漏或矛盾。       |
| 信号调查 | 分类、数据、结构化问题    | 收到混乱信号，先判断它由什么构成。      |
| 异星委托 | 提示表达、用户视角、创作任务 | 某个对象提出真实需求，用户设计更合适的方案。 |
| 失控实验 | AI 边界、幻觉、测试与修正 | 一个看似有效的结果出现偏差，用户查找原因。  |
| 观测谜案 | 多视角、证据、判断      | 同一现象有多种解释，用户比较证据。      |
| 原型工坊 | 制作、搭建、测试、迭代    | 一个作品需要在限制条件下变得可用。      |
| 星际来信 | 沟通、受众、表达       | 读取不同对象的来信，理解各自真正需要什么。  |
| 远航议事 | 协作、伦理、真实问题     | 伙伴意见不一致，用户权衡后提出理由。     |

### 4.1 使用规则

- 同一课包内优先轮换机制，避免“每集一题一故障”。
- 一集只使用一个主机制，可辅以一个轻量反转。
- 教案知识点不能倒推硬造灾难；先选择适合的机制，再决定知识如何帮助行动。
- 所有剧情、角色、对白、场景和视觉提示必须原创；不得把受版权保护作品的人物、具体情节、场景、设定或台词作“洗稿”来源。

# 5. 教案生活案例接入规则

## 5.1 三层分离

| 层级    | 内容                | 作用          |
| ----- | ----------------- | ----------- |
| 银河剧情层 | 星域、伙伴、任务关系、情绪与悬念  | 提供代入感。      |
| 案例任务层 | 校园、家庭、创作、生活中的真实问题 | 提供亲近感与学习意义。 |
| 知识行动层 | 本课要理解、判断或练习的知识    | 支持完成任务。     |

三层互相支撑，但不可互相吞没。校园案例不必变成外星危机；星际设定也不应遮蔽案例本身的真实性。

## 5.2 推荐转译方式

- 教案里的生活场景，转成星舰收到的案例档案、远程委托、模拟舱资料、观测记录或伙伴分享。
- 进入案例后，优先使用正常、现代、易理解的生活语言。
- 回到剧情时，只需显示用户的判断如何帮助完成任务，不必为每个术语补一个宇宙隐喻。

## 5.3 禁止转译方式

- 为了讲一个家庭作业案例，硬写成“星球即将毁灭”。
- 把每个知识概念都命名为新的糖、能量或宇宙物件。
- 用角色的笨拙替代真实的学习难点。
- 把课程原有生活案例原封不动塞进长对话，缺少用户任务。

# 6. 互动、反馈与奖励

## 6.1 当前可实现的互动下限

- 每集 1 次核心判断；必要时增加 1 次轻量分类、排序或选材操作。
- 题干、关键材料与选项必须在可回看的同一界面中出现。
- 用户选错后先给出“为什么这个方向不合适”的具体后果，再提供一次低压力重试。
- 不得把连续强制答题当成剧情推进的唯一方式。

## 6.2 当前奖励策略

在星粒、成长值、兑换和资产持久化尚未打通前：

- 星粒仅可作为本集即时状态反馈，不应宣传为可兑换积分。
- 每集优先呈现“任务纪念物”：一张档案、一枚航线印记、一件发现物、一次伙伴见证或一个结论标签。
- 可使用宝箱或盲盒式揭示增强惊喜，但其随机性只能影响收藏外观或叙事彩蛋，不影响学习权益、能力判断或课程解锁。
- 如无法进入用户资产库，则应称为“本集揭示”或“本次任务记录”，不能伪称为长期收藏。

## 6.3 后续接入方向

当用户资产、成就页和埋点可用后，剧情游戏可回流：

- 成就卡：完成单元且达到既定学习条件后获得。
- 航行日志：记录本集任务、判断与结果。
- 伙伴档案：记录与四位伙伴的初遇、同行和共振。
- 学习报告：记录选择、重试、停留与能力证据。

# 7. 生产禁用套路

以下内容进入脚本审校时应视为不通过，除非有明确的特殊理由：

1. 飞船损坏、能量不足、系统报警作为默认开场。
2. 拓奇或其他伙伴持续装笨，只为让用户答题。
3. 角色高频使用“太棒了”“哇”“原来如此”替代真实情绪与行动。
4. 仅把课程知识改写成星际名词，未形成事件、目标或后果。
5. 一页一个知识点、一页一道题的课件化切割。
6. 没有任务回顾，导致用户记不住题干与选项的关系。
7. 用积分、星粒、勋章等空数值代替真实反馈。
8. 默认少年男性形象为唯一玩家身份，忽视用户代入与多样性。
9. 长篇旁白解释世界观，或在学习中强迫理解糖能体系。
10. 直接模仿、复述或变形改写受版权保护的影视、小说、漫画、游戏情节。

# 8. 交付前检查清单

每节剧情游戏进入生产前，由编剧 Agent 或人工填写：

- [ ] 本集是否有区别于“飞船故障”的独立事件？
- [ ] 用户任务能否用一句话讲清？
- [ ] 是否只突出一个主要学习动作？
- [ ] 生活案例是否保留真实感，而非被硬改为星际剧情？
- [ ] 伙伴是否展现专长和缺点，而非只负责提问或夸奖？
- [ ] 关键互动是否保留题干、材料、目标与选项的上下文？
- [ ] 错误反馈是否解释原因并允许低压力重试？
- [ ] 任务结果是否有看得见的状态变化？
- [ ] 奖励是否诚实对应当前可实现的资产能力？
- [ ] 是否优先使用了已有 IP 素材库，并避免泛机器人替代？

# 9. 近期生产建议

## 9.1 先跑三个样本

不要立刻重做全部课程。优先从不同类型各选一节：

1. 概念辨析课：使用“星际档案”或“信号调查”。
2. 结构化问题课：使用“观测谜案”或“异星委托”。
3. 创作或作品课：使用“原型工坊”。

三节样本分别验证：角色可信度、生活案例接入、互动题体验、视觉资产调用和单集节奏。

## 9.2 需要后续拍板但不阻塞首批试产的事项

- 其余三位伙伴的正式姓名、色彩标识、宇航服变身设定。
- 四位伙伴的完整关系线与跨课成长弧。
- 长期资产、星粒、盲盒、成就卡和兑换之间的真实规则。
- 视觉素材库的正式目录、标签、授权与生产调用机制。
- 用户行为埋点与学习报告的回流方案。

# 10. 版本说明

本稿基于既有《银河 AI 通识课程体系与 APP 世界观总策划》、四星域课程结构、四位糖基伙伴设定及当前剧情游戏实测反馈整理。

本稿优先解决首发“能否稳定量产出不低幼、不套路、能承接学习的剧情游戏”问题；后续再扩充角色命名、文学素材库、季节主线、视觉设定集与更复杂的交互玩法。
