# 银河 APP 9月版叙事引擎中间规范 v0.1

版本日期：2026-09-11  
状态：工作中间件 / 非最终世界圣经

## 1. 核心升级

银河9月版不是重新设计一套太空视觉包装，而是在六月已有世界设定、课程体系和产品资产之上，补足“故事发动机”。

核心链路：

**世界规则 → 发生事件 → 用户判断/行动 → 产生后果 → 角色关系变化 → 知识与能力形成 → 世界留下痕迹 → 回到现实。**

世界观不仅要解释课程，还要让课程中的知识能够成为事件发生的原因、解决事件的工具和行动产生后果的规则。

## 2. 用户主体原则

用户始终是故事中的行动主体。

伙伴、AI、导航系统可以：
解释、提示、质疑、建议、协助、表达不同意见。

不得：
代替用户完成核心判断；
永远给出正确答案；
通过剧情强迫用户选择唯一答案；
因为剧情需要而把用户降格为旁观者。

第二人称叙事只能增强代入感，不能替代真实 agency。

## 3. 单集基本结构

每一课先确定真实课程目标，再设计故事。

推荐结构：

**现实/当前状态  
→ 异常或问题出现  
→ 世界规则开始作用  
→ 角色产生不同判断  
→ 用户获得信息  
→ 用户选择或完成能力动作  
→ 世界产生对应后果  
→ 必要时修正  
→ 完成任务或作品  
→ 形成能力证据  
→ 留下角色/世界记忆  
→ 轻量下一集钩子或返航现实。**

不要求每集机械套用全部节点。

## 4. 故事来源

故事可以由以下因素触发：

未知现象、错误信息、陌生生命、通讯、遗迹、自然环境、合作请求、资源限制、设计任务、创作需求、AI误判、角色分歧、真实生活问题、用户自己的作品。

“飞船故障”只是一种可选事件，禁止作为默认剧情发动机。

## 5. 知识故事化原则

课程知识不得仅替换成太空术语。

错误方式：

“AI幻觉就是离子风暴。”

正确方向：

AI输出了未经验证的信息 → 导航发生偏差 → 不同角色对信息可靠性产生分歧 → 用户寻找证据并判断 → 判断改变航行结果。

即：

**知识必须进入因果链。**

## 6. 角色原则

“糖基生命”可以作为物种/生命类别，“拓奇”应作为具体角色，而非所有伙伴的统一名称。

角色必须具有：

稳定目标；
稳定人格；
能力优势；
有趣但非贬损性的缺点；
行动习惯；
判断偏好；
与其他角色的关系；
跨集记忆；
自身成长线。

禁止把拓奇长期固定为：
笨、迷糊、总犯低级错误、需要用户不断纠正的工具型丑角。

角色可以犯错，但错误必须来自人格、信息局限或合理判断，而不是为了推动课程剧情强行降智。

## 7. 角色关系原则

伙伴之间允许：
意见不同、争论、误会、互补、合作、互相学习。

但不以霸凌、羞辱、排斥作为主要喜剧来源。

同一课程当前可继续只设置一位“主发言伙伴”，其他伙伴可通过通讯、背景、道具、记录、留言或短暂客串存在。

## 8. 失败与后果

错误选择应产生：
可理解、可恢复、具有教育意义的后果。

避免：
永久性灾难；
以死亡或严重伤害作为常规学习惩罚；
高强度恐惧；
羞辱用户；
“答错所以世界毁灭”等情绪勒索。

## 9. 世界连续性

单集不是完全清零。

允许累计：
角色对用户的记忆；
伙伴关系变化；
作品；
勋章；
星球状态；
已解决问题；
未解决谜团；
用户过去的关键选择。

但连续剧情不得成为理解课程的必要门槛。

## 10. 事实与科幻边界

所有世界内容标记为以下至少一种：

FACT：现实科学事实  
HYPOTHESIS：科学假说或合理推演  
FICTION：纯世界观设定  
METAPHOR：教学隐喻

不得将 FICTION 或 HYPOTHESIS 无标识地包装为现实科学事实。

## 12. 强制反模板规则

生产系统不得默认插入：

飞船受损；
收集星粒修船；
能量不足；
拓奇犯傻；
拓奇误操作；
唯一伙伴；
固定反派；
每课都拯救银河；
每课都发生巨大危机；
每课都以得到奖励结束。

故事规模应允许从“一件小事”到“大型星际任务”自然变化。

## 13. 最终原则

银河故事的目标不是把课程藏在游戏里。

而是：

**让用户在一个可持续生长的世界中，通过亲历问题、判断、创造和承担后果，理解AI，并把形成的能力带回现实。**
