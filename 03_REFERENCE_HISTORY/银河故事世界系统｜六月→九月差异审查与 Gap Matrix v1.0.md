# 银河故事世界系统  
## 六月 → 九月差异审查与 Gap Matrix v1.0

**版本日期：2026-09-11**  
**性质：9月 Storyworld System 上游盘整文件**  
**基准资料：**
- 6月《银河 AI 通识课程体系与星际学习世界观总策划》
- 当前《银河剧情游戏世界观与单集生产圣经 v0.1》
- 当前课程信息表 v5.0.7 候选版
- 已获得的产品反馈、生产反馈与9月新增策划原则

---

# 0. 总结论

六月版并不是一次失败的世界观设计。

相反，它已经成功建立了银河最重要的几块基础资产：

**教育内核、用户成长主线、四阶段/四星域结构、能力证明体系、星粒—知识糖—糖能的知识转化隐喻、AI伙伴理念、返航现实。**

六月文件自己已经明确区分：

> v4.5负责“教什么、怎么教、培养什么能力”；世界观负责“用户如何进入、体验、记住、证明和传播”。

这个大方向今天仍然成立。

真正的问题在于，当时缺少实际产品、剧情样本、用户反馈和成熟生产工作流，因此大量内容只能先以“概念种子”存在。世界规则、课程映射、产品功能、品牌语言、IP构想和游戏机制大量混写，导致下游容易把**隐喻当成物理规律，把产品功能当成剧情，把示例套路当成世界设定**。

9月版因此不应定义为“重写六月世界观”，而应定义为：

> **把六月的概念原型，升级成一个有明确 Canon 层级、人物关系、因果规律、时空连续性、资料来源和生产接口的 Storyworld System。**

# 1. 六月资产的五类处置结论

| 处置 | 含义 | 9月原则 |
|---|---|---|
| **KEEP 保留** | 方向经过验证，继续作为上层原则 | 不轻易修改 |
| **UPGRADE 升级** | 六月概念正确，但深度不足 | 从隐喻升级为规则/故事 |
| **DEMOTE 降级** | 有价值，但不属于世界 Canon | 移到产品、品牌或生产规范 |
| **RETIRE 退役** | 容易造成错误生产或已被反馈否定 | 不再作为默认规则 |
| **ADD 新增** | 六月基本没有，但9月必须建立 | 进入新 Canon |

# 2. 核心 Gap Matrix

## A. 顶层定位与教育内核

| 项目 | 六月状态 | 9月结论 | Gap |
|---|---|---|---|
| AI通识而非工具课 | 已明确 | **KEEP / C0** | 无方向性问题 |
| 六维AI能力 | 已建立 | **KEEP** | 与最新课程表重新对齐 |
| 用户是行动者 | 已提出探索者/建造者/判断者等身份 | **UPGRADE / C0** | 从身份口号升级为真实 agency |
| 现实返航 | 已明确为最终价值 | **KEEP / C0** | 需要贯穿各阶段，而非只在结课出现 |
| AI边界 | 有无AI对照、徒手航行 | **UPGRADE** | 进入剧情因果和用户选择 |

六月明确要求用户最终不是成为虚构世界里的“救世英雄”，而是带着作品、方法、判断、Skills与AI使用边界返回现实。这个价值目标非常稳，应成为9月不可变 Canon。

# 3. 世界本体：六月最大的未完成部分

## B. Cosmology / 世界究竟是什么

六月定义了“初始宇宙 → AI知识银河 → 四大星域 → 返航现实”，并把现实中的孩子作为真实起点。

但尚未回答：

| 未决问题 | 9月要求 | 优先级 |
|---|---|---:|
| AI知识银河是物理宇宙、数字世界、认知空间还是混合形态？ | 必须有内部 Canon 答案 | **P0** |
| 用户以什么机制进入？ | 定义，但不必全部告诉用户 | **P0** |
| 现实时间与银河时间关系 | 建立时序规则 | **P0** |
| 四星域是真实地理区域还是课程层级的表现形式？ | 统一“产品地图”和“世界地理” | **P0** |
| 不同地点之间如何航行、通讯、观测？ | 建立基本物理/技术规则 | **P1** |

**判断：六月完成的是 Map，9月必须建立 World。**

# 4. 星粒、知识糖、糖能：核心资产保留，但重新分层

六月对这一体系的教育解释其实非常完整：

**星粒 → 理解后的知识糖 → 使用后的糖能 → Skill/作品 → 长期能力资产。**

它表达的是“信息不是能力，真正理解、应用、复盘后才成为自己的东西”。这是六月最原创、最值得保留的思想资产之一。

但9月需要做一个重要修正：

### 六月
这些概念同时承担：

**教育哲学 + 世界物质 + 游戏奖励 + 儿童语言 + 品牌词。**

### 九月
拆成四层：

| 层 | 用法 |
|---|---|
| 教育模型 | 完整保留“知识代谢” |
| World Canon | 规定星粒、糖基生命等真实世界规则 |
| 产品反馈 | 只使用产品确实实现的资产 |
| 用户语言 | 按年龄与剧情需要选择性出现 |

因此：

> **“知识代谢”可以是强大的后台哲学，但不要求十岁孩子每节课听“代谢、糖能、结晶”。**

当前 CodeX v0.1 已经正确开始这个降噪：复杂术语不要求儿童记忆，只在必要时使用。

**处置：UPGRADE + DEMOTE 部分儿童显性表达。**

---

# 5. 四大星域：保留课程成长轴，但不能等同于四个课程文件夹

六月最稳定的结构是：

**创想 → 探索 → 筑梦 → 先锋**

对应从创意点、问题路径、作品构建走向真实问题解决。

这个成长方向保留。

但需要解决两个问题。

第一，**世界地理与课程阶段不能完全一一机械绑定。**

否则：

> 第一课包只能去创想星域；  
> 第二课包只能去探索星域。

世界会像四个菜单页面，而不像真实宇宙。

第二，当前六月文档基于“四阶段120课时”，而现有候选课程信息表是117条课程记录。

因此9月要规定：

> **课程表是 Course Source of Truth；世界观不得自行假定课程数量。**

四星域属于长期能力阶段，不再硬编码“30×4”等具体课数。

---

# 6. 天体现象系统：从“课程映射词典”升级为“世界因果系统”

六月有大量非常好的映射：

- 离子风暴 = 信息混乱 / AI幻觉
- 黑洞 = 高难复杂问题
- 星环 = 复习与知识连接
- 虫洞 = 跨学科路径
- 新星 = 作品发布



但目前本质仍是：

> **X知识 → Y太空名词。**

9月要增加：

> **什么条件导致Y发生 → Y会影响谁 → 用户能够如何行动 → 行动如何改变状态。**

例如离子风暴不能只是“今天要学幻觉，所以出现风暴”。

必须存在独立世界逻辑。

因此这一整块：

**Educational Mapping → Narrative Physics**

处置：**UPGRADE / P0。**

---

# 7. 星舰：保留，但必须解除“剧情发动机绑架”

六月的原始想法其实不是：

> 飞船经常坏。

而是：

> **星舰是用户工具、Prompt、Skills、作品、协作流程和判断原则的能力外化载体。**

这很好。

真正的问题发生在下游生产实现：

> “星舰”被写成了一个最廉价、最方便反复制造任务的故障机器。

因此9月：

**KEEP 星舰；RETIRE 修船母套路。**

星舰首先应该是：

**移动空间 + 能力载体 + 伙伴共处空间 + 观察窗口 + 用户个人成长痕迹。**

故障只是极少数剧情之一。

---

# 8. IP角色：这是六月→九月最大的结构升级之一

六月定义的是：

> 四类拓奇。

创想型、探索型、建造型、领航型，本质是四种能力人格化。

这在概念起稿阶段合理。

但如果长期生产，它会导致：

> 四个教学功能 NPC。

当前 CodeX v0.1 已经迈出了正确的一步：拓奇成为一个具体人物，另外三位拥有明显不同的性格优势、缺点和方法论。

9月正式结论：

> **糖基生命 = 生命类型 / 物种概念。**  
> **拓奇 = 一个具体角色。**  
> **其余三位 = 另外三个独立人物。**

“创想型拓奇”等作为分类名退出主 Canon。

### 还需新增

角色圣经必须增加六月完全没有的：

**出生/来历、私人目标、恐惧、喜好、关系历史、语言节奏、沉默方式、知识兴趣、错误模式、成长弧、角色之间共同记忆。**

尤其不再让全部角色都采用：

> 高情绪、高语速、高反应、高夸奖。

角色人格应该形成真正不同的“声部”。

---

# 9. 四人关系：从功能互补升级成人际关系

当前 CodeX v0.1 已经提出：

> 拓奇提供可能性；探索伙伴要求证据；筑梦伙伴推动实现；先锋伙伴追问影响和责任。

保留这一认知差异。

但是：

> “四位伙伴是好朋友”

不应成为当前 C0 Canon。

9月建议改成：

> **四人最终形成稳定同行群体，但相识顺序、过去经历、信任程度和关系发展需要真实发生。**

这为几十课、上百课提供天然的长期故事资产。

处置：

**UPGRADE；关系状态进入 Canon Ledger。**

---

# 10. 世界连续性：六月几乎缺失，9月新增为核心系统

这是当前最大新增模块之一。

六月主要设计：

> 用户成长连续性。

但并没有建立严格的：

> 世界历史连续性。

9月必须新增：

### Canon Ledger

| 子账本 | 职责 |
|---|---|
| Timeline | 什么时候发生过什么 |
| Character State | 人物关系、经历、知识状态 |
| World State | 地点、设施、事件当前状态 |
| Knowledge State | 已知、未知、推测、误解 |
| Promise / Thread | 伏笔、承诺、悬念、未完成事项 |

生产每一集之前读取状态，生产后写入 `episode_delta`。

这样100集才能是：

> **同一部作品的100章**

而不是：

> **100个共享皮肤的独立Prompt。**

**处置：ADD / P0。**

---

# 11. 故事发动机：六月缺失，目前 CodeX v0.1 已完成第一代

当前 v0.1 最大贡献之一，是把课程开始转化为：

**开场事件 → 任务 → 案例 → 判断 → 知识介入 → 行动结果 → 余韵。**

这明显优于六月的“知识星球 + 完成任务”。

同时八种机制：

星际档案、信号调查、异星委托、失控实验、观测谜案、原型工坊、星际来信、远航议事，

已经可以作为第一代 Seed Library。

但9月不应把八种模板重新硬编码。

最终升级方向：

> **Trigger × Goal × Constraint × Character Relation × Knowledge Action × Twist × Outcome**

机制是可组合语法，而不是40个固定模板。

处置：**KEEP v0.1作为生产 Seed；UPGRADE 为 Narrative Grammar。**

---

# 12. 开场机制：从“飞船坏了”进化，但不能又变成“每集发生异象”

当前 v0.1 把“开场异象”设为必填，并推荐冷开场。

这对第一轮生产纠偏非常有效。

长期 Canon 中则应降级为生产选项。

9月 Opening Modes 至少允许：

**日常、观察、发现、对话、委托、已发生事件、安静场景、回忆、作品触发、关系事件、科学奇观、生活入口、谜题。**

不是每节课都需要：

> “出事了！”

**处置：生产层保留；世界层 DEMOTE。**

---

# 13. 课程现实案例：当前 CodeX 方向正确，直接纳入9月原则

v0.1 将：

**银河剧情层 / 生活案例层 / 知识行动层**

严格分离，并明确校园家庭案例无需硬改成宇宙危机。

这一原则非常重要。

它意味着以后银河不是：

> 把现实题目藏进科幻皮肤。

而可以是：

> **真实世界知识和银河世界故事相互照亮。**

处置：**KEEP / P0。**

---

# 14. 产品资产与世界 Canon 必须彻底分家

六月把：

- 勋章
- 收藏
- 航行日志
- 银河舱
- 报告
- 周边
- 盲袋
- 线下营

都写进大世界观文件。

这些有价值，但不是同一层。

9月正式拆分：

### World Canon
这个世界中什么是真的。

### Product Canon
APP现在实现什么。

### Brand Asset
什么可以用于传播与商业延展。

### Runtime Constraint
当前生产工具能实现什么。

这样就不会出现：

> “因为一期没有收藏系统，所以银河世界里没有收藏物。”

也不会出现：

> “世界观写了长期资产，所以产品假装已经实现。”

当前 v0.1 已经正确规定：如果没有真正的资产持久化能力，就不能把本集揭示伪称长期收藏。

# 15. 六月实施优先级需要整体重排

六月的实施顺序主要是：

> 世界观地图 → 反馈系统 → 用户资产 → IP扩展。



经历当前实际生产以后，9月优先级应该改为：

| 新优先级 | 内容 |
|---|---|
| **P0** | 世界 Canon |
| **P0** | 四角色 Canon |
| **P0** | Timeline / Continuity |
| **P0** | Narrative Engine |
| **P0** | Course → Story接口 |
| **P0** | Safety / Fact边界 |
| **P1** | 用户成长与持久资产 |
| **P1** | 世界地图和场所丰富 |
| **P2** | 周边、音乐、角色短动画等品牌扩展 |

原因非常现实：

> **如果人物和故事没有生命，先做再多勋章、星图和周边资产，也只是在扩展一套空世界。**

# 18. 对当前 CodeX v0.1 的正式定位调整

建议将现文件：

> 《银河剧情游戏世界观与单集生产圣经 v0.1》

后续改名为：

> **《银河剧情游戏生产规范 / Narrative Production Spec v0.2》**

原因不是降低它的重要性，而是让它职责更清楚。

它负责：

**单集如何生产、什么不允许发生、互动怎样设计、现实案例怎样接入、当前产品边界是什么。**

而它本身也明确承认：自己不替代完整 IP 设定集，重点解决当前量产中的低幼、套路和知识硬插问题。

未来结构应为：

```text
World Canon
+ Character Canon
+ Timeline / Canon Ledger
+ Controlled Reference Library
+ Course Source of Truth
          ↓
Narrative Production Spec
          ↓
Story Profile
          ↓
李光生产系统 / Agents
```

# 19. 九月 Storyworld System 的质量验收标准

最终我们不能只问：

> “设定好不好看？”

而要同时通过以下五种测试：

### Canon Test
同一个事实问不同 Agent，答案是否一致？

### Continuity Test
第80课是否会否定第12课已经发生的事实？

### Character Test
拿掉角色名字，只看一句话和行动，能否大致判断是谁？

### Education Test
去掉太空视觉以后，这一集是否仍然有真实学习动作？

### Story Test
去掉知识点以后，这个事件、人物关系和选择是否仍然具有基本叙事成立性？

真正好的银河单集应该：

> **课程和故事互相需要，但彼此都不是对方的伪装。**

# 20. Gap Matrix v1.0 最终结论

六月最值得继承的不是那些名词，而是三个基础思想：

> **孩子是主体。**  
> **知识必须转化成能力。**  
> **最终必须返航现实。**

九月最重要的升级也可以归结为三个词：

> **因果、人物、连续性。**

六月完成了：

> **“银河里有什么。”**

九月必须完成：

> **“银河为什么这样运转、谁真正生活在这里、此前发生过什么、接下来为什么会发生故事。”**

因此9月不是对六月做装修。

而是：

> **把六月的概念世界第一次建设成真正可长期居住、可连续叙事、可由多人和Agent共同维护的故事宇宙。**
